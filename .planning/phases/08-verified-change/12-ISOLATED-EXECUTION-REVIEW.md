# 실제 격리 실행 검토 기록

대상은 [후속 계획](11-ISOLATED-EXECUTION-PLAN.md)의 ISO-01~09다. 이전 독립 2·3심의 소스 SHA 이후 변경이므로 이전 심사 통과를 이번 변경의 독립 심사로 계산하지 않는다. 아래는 같은 구현 담당자의 요구 검토·실패 반례·최종 실행 확인이며, 세 명의 독립 심사가 아니다.

## 요구 검토

기존 서비스·CLI·MCP와 자료 계약을 유지한다. 기본 evaluator의 실행 불가 응답을 실제 로컬 격리 연결로 교체한다. 앱 명령은 앱 작업 안에서 실행하고 화면 판정은 기존 `run_flow`를 별도 검사 작업에서 재사용한다. 명령 결과의 해석과 원본 사본 대조는 공통 함수로 사용한다. 새 DB·테이블·필수 필드·서버·별도 실행 대기열은 없다.

Environment의 기존 이미지·실행기·OS·Python·Node·패키지 도구·브라우저·잠금 파일·글꼴·정책 필드를 실제 실행과 대조한다. 같은 검사·요청의 시간·출력·자료·정리 제한을 유지한다. 입력 해시를 자동 갱신하거나 isolated 요구를 낮추지 않는다.

## 실패 반례와 보강

| ID | 재현한 문제·위험 | 보강 | 근거 |
|---|---|---|---|
| ISO-F01 | 기존 정책이 Chromium 내부의 빈 디렉터리 이동을 차단 | 검사 작업에 chroot 호출을 허용하고 전체 권한 제거를 유지 | 실제 최초 실행 JSON, 정책 실패 시험, 실제 headless 실행 |
| ISO-F02 | Docker 29의 소문자 `no such object`를 정리 실패로 오인 | 오류 문구 대소문자와 실제 조회 결과를 함께 처리 | 실패 시험과 실제 제거·부재 조회 |
| ISO-F03 | 실행기 확인 뒤 실제 명령 통로 없음 | 확인한 작업 ID에 한정한 앱·검사 명령 연결 | 실패 시험, 실제 작업별 접근 분리 |
| ISO-F04 | 환경 파일이 있어도 실제 버전·글꼴이 다를 수 있음 | 이미지 안에서 대조 후에만 승인한 명령 실행 | 버전·글꼴·브라우저·OS 변조 거부 시험 |
| ISO-F05 | 출력 초과·미정이나 수정된 사본으로 후속 검사 가능 | UTF-8 합산, 미정 차단, 종료 후 사본 대조 | 단위 반례와 실제 출력·사본 변조 시험 |
| ISO-F06 | 반복 검사에서 읽기 전용 입력을 다시 작성 | 고정 입력과 검사 코드 준비를 요청당 한 번으로 제한 | 반복 검사 실패·통과 시험 |
| ISO-F07 | 실행기 기본 로그 순환으로 출력 앞부분 누락 가능 | 파일 로그를 끄고 시작과 동시에 직접 표준 출력 수집 | 정책 실패 시험, 실제 실행 정책 조회 |
| ISO-F08 | 고정 10초 정리가 더 짧은 승인 한도를 무시 | 요청별 정리 한도를 생성·로그 정리와 공유 | 정리 한도 실패·통과 시험 |
| ISO-F09 | 작업 시작 실패 후 같은 요청에서 재시도 가능 | 작업 응답 오류 시 후속 검사 중지 | 작업 시작 실패 반례 |
| ISO-F10 | 화면 제공 준비를 기다리지 않으면 일시 접속 거부 | 원래 제한 시간 안에서 TCP 준비 확인 | 실제 TCP 시험, HTTP 요청을 보내지 않음 |

ISO-F01의 근거는 [Chromium credentials.cc](https://chromium.googlesource.com/chromium/src/sandbox/+/refs/heads/main/linux/services/credentials.cc), [Moby 기본 정책](https://github.com/moby/profiles/blob/main/seccomp/default.json), [Playwright Docker](https://playwright.dev/python/docs/docker)다. `chroot` 허용이 실행 권한을 부여하지 않으며 운영체제의 권한 검사는 유지된다. SYS_ADMIN·SYS_CHROOT 추가, Chromium 보호 해제, 사용자 장비 IPC 공유는 하지 않는다.

처음 실제 비교 시험은 잘못 준비한 fixture SHA로 거부됐다. 시험 환경에 승인한 fixture SHA를 지정한 뒤 같은 기준을 다시 실행했다. 제품의 fixture 검사를 완화하지 않았다. 그 실패 기록도 보관한다.

## 최종 실행 확인

최종 명령·소스·배포 파일·실행 환경·실패 및 통과 자료는 [실행 기록](evidence/2026-10-14-isolated-final.json)에 연결한다. 집중 시험의 중복 수를 전체 시험에 더하지 않는다. 화면 검사는 모두 headless이며 브라우저 오류·차단 자료와 정리 여부를 결과에 보관한다. 반복 취소 시험은 하위 Node 실행까지 생성한 뒤 소유한 작업의 실제 부재와 다른 기존 작업의 보존을 확인한다.

## 남은 조건

- 자동 수정·재검사와 비용 예약을 같은 새 요청에 연결하는 D3는 별도 과제다.
- 이미지 의존성의 잠금 파일 재구성·일반 시험 도구별 보고 수집·첫 사용 준비 자동화는 미완료다.
- 사용자 환경의 Docker와 검사 이미지를 신뢰한다. 앱 사본의 디스크 용량 할당·다른 장비·실행기·악성 코드의 장비 전체 보호는 이번 실행 근거에 포함하지 않는다.
- 실제 사용자·실제 저장소 3개 이상의 비교·반복 사용에 따른 제품 가치는 D4에서 확인해야 한다.

최종 회귀에서 Docker가 `max-size:-1`을 인자로 거부하고, 인자를 제외하면 기본 `20m`를 합치는 동작을 확인했다. 파일 로그 설정을 완화하지 않고 `--log-driver none`과 `start --attach`로 변경했다. 시작 직후 출력이 누락되지 않고 소유 작업을 종료한 뒤 출력이 확정되는 실제 시험을 추가했다. 기본 Chromium 실행 파일 부재로 기존 화면 시험이 실패한 기록도 보관했으며, 시험용 Chromium 준비 후 같은 기준을 다시 실행했다.

최종 확인: 일반 시험 2,234개, 기존 headless 화면 시험 29개, 실제 격리 E2E 11개 통과. 타입 오류 0개, Ruff 검사·344개 파일 형식 검사 통과. 별도 설치본의 Python 모듈 151개가 소스·wheel과 일치하며 설치본에서 실제 격리 명령·정리를 확인했다. 마지막 조회에서 소유한 격리 작업은 0개이고 기존 다른 실행 3개는 같은 ID로 유지됐다. 설계 정합성 검사는 21개 정의·203개 필드·79개 예시·39개 링크를 확인하며 구현·제품 효과 근거로 합산하지 않는다.
