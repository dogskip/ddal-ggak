# 검증 가능한 화면 변경의 용어

| 용어 | 의미 | 구분할 대상 |
|---|---|---|
| 사례(case) | 한 요청과 승인된 수용 기준의 묶음 | 실행과 결과 |
| 실행(run) | 한 사례의 기준과 후보를 확인하는 작업 한 번 | 반복 실행·사례 변경 |
| 기준(baseline) | 변경 전에 비교 대상으로 승인한 상태 | 자동으로 선택한 최신 상태 |
| 후보(candidate) | 요구사항을 만족하는지 확인할 변경 상태 | 원본에 반영한 상태 |
| 요구(requirement) | 사용자가 수용 여부를 판단할 명시적 결과 | 추론한 화면 의도 |
| 검사(check) | 하나의 기대 결과를 확인하는 절차 | 요구 전체의 만족 |
| 보존(preserve) | 변경 전후에 유지해야 하는 결과 | 새로 달성할 결과 |
| 목표(target) | 이번 변경으로 달성할 결과 | 기존 실패의 자동 예외 |
| 정책(policy) | 권한·범위·상한·무결성에 관한 조건 | 제품 동작 요구 |
| 완료 가능(ready) | 지정한 필수 범위의 확인이 완료된 판정 | 전체 앱의 무결함·원본 반영 |
| 확인 불가(blocked) | 실패 또는 자료·환경 부족으로 완료를 판단할 수 없는 판정 | 성공으로 계산한 건너뜀 |
| 검토 필요(manual-review) | 사람이 범위·의도·후속 조치를 결정해야 하는 판정 | 필수 실패의 승인 |
| 반영(apply) | 확인한 변경을 선택한 원본에 적용하는 동작 | 검사·내보내기 |
| 복구(rollback) | 반영 이전 상태로 되돌린 결과를 확인하는 동작 | Git 전체 초기화 |
| 불명(unknown) | 실제 파일 상태와 복구 결과를 확정할 수 없는 상태 | 자동 덮어쓰기 허용 |
| 보장 수준(assurance) | 실행 경계에 대해 확인한 보호 범위 | 검사 결과의 판정 |
| 자료(artifact) | 결과 판단과 재현에 필요한 기록·파일 | 공개해도 안전하다는 승인 |
