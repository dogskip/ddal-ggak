# 검증 가능한 화면 변경: 설계 전 분석

조사일: 2026-10-14. 대상: 현재 작업 폴더 전체. Git 기준: `3e53e93c8ec27e026c8271de5522609063ae1ca3`.

이 문서는 이번 사용자 요청과 앞선 경쟁 조사에서 추출한 판단 기준이다. 구현 지시나 출시 승인이 아니다. 기존 코드·사용 안내와 충돌하는 내용은 앞으로 구현할 목표 설계로만 해석한다. 기존 GSD 관련 장기 목표를 삭제하지 않고 이번 개발 우선순위의 판단에서 제외한다.

## 1. 요청과 성공의 정의

사용자는 경쟁력·실용성·희귀성과 GitHub 스타 10만 개의 가능성을 원한다. 이번 요청은 인터넷 조사와 3심 검증을 통해 더 적합한 설계를 문서로 확정하고, 관련 기능·저장 구조·필드까지 명시하는 것이다. 실제 구현·배포·외부 사용자 모집은 요청 범위에 포함하지 않는다.

첫 제품 목표의 후보는 **기존 React·TypeScript 앱의 제한된 화면 변경을 완료하고, 요청한 화면과 핵심 동작 및 기존 기능 보존을 확인할 수 있는 자료를 제공하는 것**이다. 기능 수·모델 수·자체 점수는 경쟁 우위를 대신하지 않는다.

100점·절대적 신뢰성·모든 반론의 제거는 문서 검토로 보증할 수 없다. 설계 정합성, 구현 수용 기준, 실측된 제품 효과를 별개로 판정한다. 비교 성능과 반복 사용은 구현 이후의 조건이며 현재 결과로 선언하지 않는다.

|---|---|---|---|
| 현재 JSON 파일 보강 | 사례별 검사 자료·변경·반영·복구 | 파일별 원자적 교체·잠금·중단 복구 필요 | 사용 후보 |
| SQLite 추가 | 단일 작성자 대기·복잡한 조회·관계 제약을 트랜잭션으로 관리할 필요 | 파일 자료와 DB 간 정합성·전환·복구 책임 추가; SQLite도 한 시점 한 작성자 | 측정된 필요가 생기면 재검토 |

사용자의 DB·테이블·컬럼 요구에는 **실제 DB 사용 여부와 이유, 파일 저장의 논리 테이블·관계·필드·제약**으로 응답한다. 대상 앱의 사업 데이터나 DB 구조를 임의로 생성하지 않는다.

## 6. 실행과 반영의 대안

1. 임시 복사본만 사용: 편리하지만 임의 프로젝트 명령과 생성 코드의 호스트 접근을 격리하지 못함. 원본 사본 보호로만 표시한다.
2. 격리 실행을 기본으로 사용: 검증 기준을 별도 읽기 전용으로 제공하고, 인증·호스트 원본·외부 네트워크를 제외한다. 실행 환경이 없으면 불가로 종료한다. 컨테이너 자체가 절대적 보호를 제공한다고 주장하지 않는다.
3. 사용자 승인 프로젝트의 개인 환경 실행: 실행 위험을 사용자가 수용한 제한 모드이며 격리 결과와 동일하게 표시하지 않는다. 자동 변경의 검증 수준은 별도로 유지한다.

원본 반영은 검사와 분리한다. 먼저 변경 묶음과 결과를 제시하고, 명시적으로 선택한 반영만 하는 후보다. 여러 파일의 외부 관찰상 원자성을 약속하지 않는다. 반영 기록과 원본 사본을 먼저 보존하고, 현재 해시가 기대 값과 다르면 중단한다. 성공은 대상 파일 전체의 반영 후 해시 확인으로 정의한다. 해시 조회 직후 외부 편집까지 막을 수는 없으므로 보장 시점과 동시 편집 한계를 명시한다. 예상 밖 현재 값·복구 불명·동시 쓰기 제어 불가에서는 자동 덮어쓰기 없이 변경 묶음 내보내기만 제공한다.

1심 선행 지적은 SQLite의 작성자 제한과 해시 확인 뒤의 외부 편집 위험이었다. 위 대안과 반영 계약에 반영했다. 공식 근거와 독립 심사 기록은 [1심 연구](2026-10-14-official-sources.md)에 보관한다. 이 조건을 전제로 B의 목표 설계 문서를 작성한다.

## 7. 3심 절차와 판단 규칙

| 심사 | 대상 | 담당과 자료 | 통과 조건 |
|---|---|---|---|
| 1심 | 목표·공식 근거·대안·추가 구성의 필요 | 배경 연구자의 독립 조사 및 본 분석 | B의 사용 이유와 한계, 저장·실행 경계가 직접 목표·실패 위험에 대응 |
| 2심 | 작성된 설계의 반례·복구·필드·동시성·편의성 | 독립 검토자의 실패 중심 검토 | 중대 지적을 반영하거나 근거 있는 제외 결정을 기록 |
| 3심 | 수정된 설계 전체·추적 관계·검증 결과 | 별도 최종 검토자와 재현 가능한 문서 검사 | 중대 미해결 지적 없음; 모든 요구에 설계·수용 기준 대응 |

동일한 설계자가 세 번 자기 승인하는 절차로 대체하지 않는다. 최종 판정은 문서 확정 여부이며 제품 출시·표준 인증·경쟁 우위의 판정이 아니다. 1심에서 후보가 부적합하다고 판단되면 설계 본문 작성에 앞서 후보를 수정한다.

## 8. 제외 범위와 다시 판단할 조건

현재 범위에서 제외: 웹 관리 화면, 서버·작업 대기열·외부 DB, 사용자 계정·협업, 대상 앱 DB 변경, 임의 언어·브라우저 전체 지원, 자동 배포, 새 모델 제공자의 일괄 지원, 별점 성장 예측.

재검토 조건은 기존 검사 재사용의 한계, 실제 사용자 과제의 실패 분포, 사례 검색과 동시 작성의 측정 결과, 격리 실행의 도입 실패, 지원 대상별 반복 사용 자료다. 구현 시간·인원·일정은 기존 문서에서 차용하지 않는다.
