# Approval and evidence boundaries

A dry plan can describe a blocked operation. Its process exit alone is not a ready receipt.
Target checks must distinguish the baseline from the candidate; preserve checks protect behavior
that already worked. Review a discovered draft with the owner before promoting it.

Host execution can run repository-defined commands with the owner's permissions. It is not an
OS security boundary. The default isolated executor needs its own observed environment.
Provider transfer and application require separate grants; neither follows from permission to inspect.

Use existing components first, then standard platform features, then a direct local change.
Introduce a new dependency or abstraction only when the existing code cannot meet an explicit
requirement. Do not make up reuse percentages, time savings or provider success rates.

Ready applies to the saved case, source and environment that were actually checked. It does not
establish deployment, remote CI success or effectiveness of an untested model.
