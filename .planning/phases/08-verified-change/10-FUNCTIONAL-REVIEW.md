# 기능 보강의 3심 검토 기록

대상은 이번 공통 서비스·실제 검사 연결·새 CLI·MCP와 관련 공통 경계다. root가 통합과 1심을 맡고, 각 담당은 자신이 작성하지 않은 모듈을 2·3심으로 교차 검토했다. 이전 반영 모듈의 3심과 전체 제품의 완료 판단을 구분한다.

## 지적과 처리

| ID | 재현된 결함 | 보강 |
|---|---|---|
| FR-01 | 없는 저장소의 상태 조회가 폴더 생성 | 쓰기 초기화를 분리하고 조회는 생성 없이 실제 자료 검증 |
| FR-02 | SDK 해석 후 검사만으로 원문 초과·중복 키 수용 | SDK의 stdio를 재사용하며 해석 전 바이트·깊이·중복·UTF-8·NaN 검사 |
| FR-03 | 입력 상위 링크를 해석하며 경로 경계 우회 | 원문 상대 경로를 검증한 뒤 공통 부모 파일 접근 적용 |
| FR-04 | CLI가 저장소 링크를 실제 경로로 바꾸어 우회 | 새 명령은 원문 경로를 공통 서비스에 전달 |
| FR-05 | 공개 보고서의 자유 실패 문자열에 민감 원문 포함 | 기본 보고에서 해당 원문 제외, 개인 자료 포함은 별도 선택 |
| FR-06 | 정상적인 큰 실행 자료를 소스 크기 상한으로 거부 | 자료 상한과 전체 내보내기 상한 사용 |
| FR-07 | 실행 사본 변경 후 원래 후보 해시 반환 | 실행 후 고정 소스·권한·목록 대조, 불일치·후속 중단 기록 |
| FR-08 | 승인 출력 한도가 검사기에 전달되지 않거나 검사마다 초기화 | 요청 한도 전달, 기준·후보의 남은 한도 공유 |
| FR-09 | 취소 정리 실패를 timeout 변환이 정상 정리로 처리 | 원래 정리 실패 유지·추가 실행 중단 |
| FR-10 | timeout의 부분 출력량을 0으로 처리 | 미정값을 구분하여 정책 확인 불가로 중단 |
| FR-11 | 미리보기 시작 실패의 부분 출력량을 0으로 처리 | 같은 미정 규칙 적용, 최종 재검토 대상 |
| FR-12 | 검사별 시간만 확인하고 사례의 단계 시간 무시 | 실행 전체·검사·단계 기한 중 최소값 사용 |
| FR-13 | CLI 환경 오류의 종료 값과 취소 후 ID 누락 | 불가=2·취소=130, 알려진 case/run/반영 ID 유지 |

최종 재검토에서 위 대상의 필수 잔여 지적은 없었다. 2심의 집중 시험 중 80ms 기한이 입력 준비 중 끝나 검사기 정리를 관찰하지 못한 1건은 단독 재실행에서 통과했다. 해당 시험은 검사기가 시작한 뒤 단조 시계를 진행하도록 바꾸어 의도한 취소 지점을 확정했다. 실제 실행 기한과 검사의 허용 기준을 완화하지 않았다. 변경 후 해당 조율 시험 33개가 통과했다.

배포 검사에서는 내부 시험 자료의 절대 심볼릭 링크가 소스 배포에 포함되는 실패를 재현했다. 내부 증거 폴더를 배포에서 제외한 뒤 sdist→wheel 구성·별도 설치·모듈 148개 일치·계약 해석·CLI/MCP 등록을 확인했다. 원래 증거 자료는 삭제하지 않았다.

모든 지적은 동작 실패나 실제 임시 자료의 반례로 확인했다. `red` 기록의 수집 오류는 기능 거부 시험의 통과로 계산하지 않는다. 추가 구성이나 성능 개선을 위한 제안은 필수 결함과 섞지 않는다.

## 최종 확인 기준

수정 후 지정 소스 SHA가 변하지 않는 상태에서 집중·관련 회귀·실제 headless·stdio·타입·형식·설치 검사를 확인한다. 시험 범위가 겹치면 수를 합산하지 않는다. 각 심사의 최종 범위·지적·재확인·SHA는 최종 실행 기록에 연결한다.

독립 심사에서 필수 잔여 지적이 없어도 실제 격리 작업·새 자동 수정·환경 전체 입증·제품 효과가 완료되는 것은 아니다. 사용 범위와 미완료 조건은 [기능 평가](09-FUNCTIONAL-ASSESSMENT.md) 및 [사용 안내](../../../docs/VERIFIED-CHANGES.md)를 유지한다.
